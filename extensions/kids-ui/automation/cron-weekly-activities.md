# Additional evidence for the existing weekly parent report

Retain the current read-only job and automatic parent delivery. For each child,
read `kids_activity(action="evidence", childId=...)` along with the existing
conversation evidence and notes. Filter actual attempt timestamps to the exact
weekly collector window; an activity published earlier can be attempted this week.

Report quiz attempts/completions separately from child-message counts. Overall
active days may union chat/voice and quiz dates in the child's timezone. Do not add
the two day counts or call generated days completed activities. Mention one useful
learning outcome, distinguishing independent first answers from hints/retries.
Clarification submissions are ungraded; do not count them as incorrect answers.
Use the submitted reasoning alongside the model's feedback, and describe narrow
observations rather than treating a model verdict as proof of broad mastery.
There are three optional challenges per prepared day; report actual per-challenge
completions, including carried-over work completed this week. Remaining optional
challenges are not missed homework, and one daily artwork pair is not three
separate learning events.
Deduplicate stable attempt IDs and linked conversation discussion. Excitement,
scene generation and an invitation delivery are not independent learning evidence.

Keep missing source coverage explicit, including `activitiesOmitted` and
`attemptsOmitted`. A tool failure is not inactivity. Existing
delivery receipts remain the invitation ledger; quiz attempts do not prove the
child saw a push or directly answered a particular notification. Keep the report
short and preserve the existing no-message-tool rule.
